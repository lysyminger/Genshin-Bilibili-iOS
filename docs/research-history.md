# 研究过程

| 阶段 | 发现与结果 |
| --- | --- |
| v0.1–0.5 | 解决签名头空间、段对齐/多余load command和懒绑定问题，诊断库能够启动 |
| v0.6–0.8 | 定位MiHoYoComboManager登录入口，接入参考包中的B站SDK组件 |
| v0.9–0.11 | 真实combo认证通过；修复请求body及indexed回调JSON类型 |
| v0.12–0.15 | 定位GF/QD路由及目录差异；只改渠道不能完成区服调度 |
| v0.16–0.18 | 只换版本字符串仍失败；观察请求构造路径，未定位通用seed生成算法 |
| v0.19 | 两次独立安卓启动验证配套值稳定，固定匿名元数据及资源字段对照通过；iPad实际二级缓存retcode=0、有RegionInfo，随后进入世界加载报314302；尚未确认完整进入世界 |

短dispatchSeed为16位十六进制，不能与目录中较大的Ec2b数据混为一谈。旧的Base64推测已纠正。客户端左下角显示的版本文本也不等于实际发送的调度query。

区服调度成功、combo认证成功和进入世界是三个不同阶段。早先“已进入世界”的反馈已被用户后续澄清撤回：iPhone还在下载，iPad加载世界时报314302。独立日志确认combo成功和配套改写，iPad实际调度缓存也已解码成功；完整进入世界仍未验证，314302的具体原因未确认。
